LESSON 01 · BLOCKCHAIN FOUNDATIONS

Smart contracts on Bitcoin, then Arkade

The useful mental shift: a smart contract is not necessarily a program living on a chain. It can be a rule that controls how a specific piece of value may move.

One-sentence model. Arkade lets an application express payment and financial rules as Bitcoin-verifiable spending policies, while many transitions happen off-chain as VTXO state.

1. The general blockchain idea

A blockchain gives many parties a shared way to agree on state without one database owner. A smart contract adds rules: “these funds can move if condition A, B, or C is satisfied.” On Ethereum-like systems, the contract is commonly a deployed program with persistent storage, and a call pays gas for execution.

Bitcoin is more deliberately constrained. Its native contract language, Script, validates spending conditions. The state is mostly UTXOs: spendable outputs whose locking rules are checked when consumed. Bitcoin contracts tend to be transaction-shaped: they describe allowed spending paths rather than behaving like continuously running objects.

2. What Arkade changes

Arkade introduces VTXOs—virtual transaction outputs—so compatible wallets can exchange value and obtain fast pre-confirmations off-chain. The operator coordinates these transitions; Bitcoin transactions periodically commit the state and preserve unilateral exit paths. Arkade’s own overview emphasizes that it is not another blockchain and does not require a separate native token or consensus system.

So an Arkade contract is best imagined as a programmable envelope around value: for example, “the player may claim this reward now,” “the tournament escrow can be released when both parties approve,” or “the player can recover after a deadline.” The SDK’s ContractManager watches contract scripts and their VTXOs; it is not a virtual machine executing arbitrary game code.

4. Cost intuition

Do not begin with “How much gas does deployment consume?” For Arkade, constructing a script and registering it with a wallet/indexer is generally not an on-chain deployment event. The cost-bearing moments are funding and spending: the BTC value itself, a quoted operator or route fee when one applies, and Bitcoin miner fees whenever a transaction reaches the base chain.

For an exact quote, use the SDK/operator’s fee-quoting API for the concrete transfer. Treat any numerical estimate without the operator, transaction shape, fee rate, and network as provisional. An inactive VTXO also has a lifecycle: it must be renewed before expiry to preserve the normal unilateral-exit guarantees.
