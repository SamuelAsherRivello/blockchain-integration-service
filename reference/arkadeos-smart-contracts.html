ArkadeOS smart contracts

A compact map of the concepts, differences, game ideas, and fee model.

Core model

Bitcoin
The settlement layer: transactions, UTXOs, Script, signatures, and miner fees.
Arkade
A programmable Bitcoin extension using VTXOs: virtual outputs that support fast off-chain state transitions and later Bitcoin settlement.
Contract
A spending policy: the set of conditions and paths under which a VTXO can be spent, recovered, or claimed.
Operator
A service that coordinates off-chain transitions and batches them into Bitcoin commitments; it does not replace the user’s signing authority.
Contract call
Usually a spend along one contract path, producing new VTXOs or an on-chain transaction—not a gas-metered function invocation.

Arkade differences

  • No separate Arkade consensus chain or gas token.
  • No EVM-style global mutable contract storage.
  • Rules live in Bitcoin Script/Taproot-style spending paths and transaction structure.
  • Fast activity can be off-chain and pre-confirmed; Bitcoin provides settlement and exit.
  • Self-custody includes presigned fallback paths, but expiry creates liveness obligations.
  • Fees are quote-, transaction-size-, operator-, and Bitcoin-network-dependent.

Cost model

ActionTypical direct cost
Construct/register a contractUsually 0 sats as a local/script/indexer operation; no EVM deployment gas.
Fund the contractBTC amount funded + any Arkade/operator transfer fee; quote it through the SDK/operator.
Use a contract path off-chainThe value moved plus any quoted operator fee; no separate universal gas price.
Settle, board, or unilaterally exitBitcoin miner fee based on transaction size and fee rate; a multi-step exit can require multiple transactions.

Rule of thumb: cost ≠ “contract code execution.” Cost = value moved + Arkade service/route fee, when applicable + eventual Bitcoin on-chain fee.
