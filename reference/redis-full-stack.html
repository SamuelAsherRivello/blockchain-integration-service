Redis in the stack

PartTypical responsibility
FrontendDisplay data and send requests to an API.
Backend APIValidate requests and apply application rules.
Primary databaseStore authoritative application records.
RedisCache repeated reads, share sessions and counters, support queues and messaging.
Key
A name used to find data, such as listing:42.
Cache hit
The requested cached value exists.
Cache miss
The requested cached value is absent.
TTL
Time to live: how long a key remains before automatic expiration.
Invalidation
Removing or replacing a cached value after its source changes.

RAM storage does not mean Redis must lose everything on restart. It supports disk persistence; durability depends on configuration. A cache can be rebuilt, while sessions and queued work need deliberate loss and recovery policies.

In a typical web app, the browser calls your API and the API accesses Redis. Redis is a separate service that multiple backend instances can share.
